# 处理 Brainstorming 新论文

仅在用户实际要求处理这些目录的新论文时执行。讨论或编辑技能、引用触发词、开启会话或打开仓库都不触发扫描；不创建监听或定时任务。若用户指定 inbox 或其他来源，按指定来源及相应技能执行。

## 按用户意图执行

三个请求都先扫描并展示本批次候选，再按意图处理：

- **检查新论文：** 有候选时请用户选择全部、编号或暂不入库，收到选择后才入库。
- **入库新论文：** 直接入库并归入工作区，无需再次确认。
- **解析新论文：** 入库并归类后逐篇分析、生成解析文件。单纯入库时，PDF 转 Markdown 属于入库步骤，不额外生成解析文件。

用户指定目录、编号或文件时按指定范围处理，否则以本次未忽略、未入库的论文为准。课件、笔记、海报不当作论文入库；类型不明的项目仍列出待核实，明确的论文照常处理。没有候选时报告结果，不补扫历史库。

## 扫描与筛选

从仓库根目录运行：

```bash
bash .claude/skills/new-papers/scripts/scan.sh
```

脚本在 `/mnt/e/Study/Brainstorming` 与 `/mnt/c/Study/Brainstorming` 中选择唯一存在的根目录，可用 `SCHOLARAIO_BRAINSTORMING_ROOT` 指定来源。来源不唯一、目录不可访问或扫描失败时，说明原因，保留上次扫描记录。若配置了非默认论文库路径，先按当前 `Config` 校准脚本查库路径。

扫描覆盖下表的来源目录及子目录，只读取 PDF（扩展名不区分大小写）和库中元数据，不解析正文、不调用 API、不移动源文件。结果见本技能下的 `state/report.json` 和 `state/candidates.md`。

1. 按 SHA-256 合并内容相同的文件。`library_matches` 的 `sha256` 表示内容已在库中；`source_file` 或 `title` 只是线索，须核验库中元数据，仍不能确认的列为候选。
2. 按目录分组展示 `candidates` 和待核验项目，保留编号、文件名、相对路径与修改时间；列表过长时给清单链接与数量。首次扫描称“尚未确认入库的现有 PDF”；后续区分新增内容和前次待处理项。修改时间不代表存入时间。

## 入库

获得授权后，按[入库技能](../ingest/SKILL.md)处理。仅将选中的 PDF 复制到配置的 inbox，保留原件且不覆盖同名文件。检查其他 inbox，必要时用独立配置隔离批次，再运行 `uv run scholaraio pipeline ingest`。MinerU 不可用、失败或 token 过期时立即告知用户并暂停 PDF 解析；未经授权不得切换解析器。

记录本批次“源文件 → 库中 UUID”。以实际写入或去重后核实的库中记录为准；失败和 pending 保留为待处理，下次扫描仍按实际库记录核验。

### 归入已有工作区

仅处理本批次已核实的库中记录；用户要求不归类时跳过。先用 `uv run scholaraio ws list` 核对已有工作区。用户指定的工作区优先；若不存在，说明原因，不改投。未指定时按下表归类：

| 来源目录（相对于 Brainstorming） | 默认工作区 |
| --- | --- |
| `Error Correction/` | `error-correction` |
| `Architecture/3.Trapped-Ion/` | `trapped-ion` |
| `Architecture/4.Neutral-Atom/` | `neutral-atom` |

标题和摘要显示另一个已有工作区更合适时，在批次报告中说明理由并提出建议，本批次照默认归类，不暂停入库或自行修改映射。默认工作区不存在或来源不明确时，按主题匹配，找不到就归入已有的 `misc`。若 `misc` 也不存在，留在主库并报告，不自动创建工作区。

按工作区执行 `uv run scholaraio ws add <工作区> <UUID>...`，仅用本批次核实的 UUID；隔离入库后须使用能解析这些 UUID 且指向实际工作区的配置。核对 `refs/papers.json`，区分新增、已有和未能加入的论文。

### 逐篇解析与报告

解析请求按[论文解析技能](../paper-analysis/SKILL.md)读取本批次核实记录的 L1/L2/L4 和关键图表，无需逐篇再确认。将 `Author-Year-Keywords-Analysis.md` 保存到主要归属工作区（含 `misc`）；无可用工作区时按主题选输出路径。缺少全文或解析失败的论文单独报告，其余照常解析。

报告入库、去重、失败或 pending 的结果，以及工作区归属、未归类原因和已生成的解析链接。

## 源目录的论文 PDF 命名

三个目录统一用 `作者 - 论文标题.pdf`，保留原题措辞、大小写和缩写，标题内的冒号写作 `꞉`（U+A789）。不默认加年份、会议名或 DOI；用户要求标记 arXiv 版时在 `.pdf` 前加 ` arXiv`。缺少该后缀不代表正式发表。

单作者可用全名，双作者用 `姓 & 姓`，三作者用 `姓, 姓 & 姓`，四位及以上默认用 `首作者姓, et al.`。保留重音符号、团体名和中文姓名；中文作者可用 `, 等` 缩写。

四位及以上时，只将名单中确属该论文作者的人按原文顺序列在首作者与 `et al.` 之间，例如 `Bluvstein, Lukin, et al.`；已是首作者的不重复。仅按用户指定更新名单：

- Murali
- Lukin

仅用于在这三个目录新保存论文或按要求提出改名方案。扫描、入库和解析不改名或覆盖源文件；缺少作者前缀也可能是论文。此规则不用于非论文材料、主库目录或解析文件。

## 忽略记录与本地状态

“暂不入库”只跳过本次。用户明确要求以后忽略时，将对应 SHA-256 追加到本技能的 `ignored.json` 并去重；内容变化后可重新成为候选。

历史基线已记录在 `ignored.json`：按 Asia/Hong_Kong 的文件修改时间，将早于 2026-11-01 的 38 个未匹配 PDF 按内容忽略。这是一次性清单，新发现的不同内容照常检查。

`ignored.json` 随 Git 同步，只保存内容哈希；`state/` 下的扫描历史和清单仅保存在本地。
